# 架構與取捨導讀

英文權威來源：[Target architecture](../architecture/target.md)、[ADR-008](../architecture/adr-008-investment-operations.md)。
類型：閱讀摘要；涵蓋主要邊界、技術引入理由與限制，不是完整翻譯。
來源版本：`refactor/asset-management-platform` 分支的未提交草稿，2026-10-30。
同步狀態：草稿；正式決策、替代方案與完整後果以英文為準。

採漸進重構。先把持倉估值整理為不依賴 FastAPI、ORM 或模型的純領域核心，保留舊系統及安全測試，再建立有資料版本、權限與對帳能力的新工作流程。現有加密資產表格不能直接改名當成股票投資帳簿。

目標流程是資料匯入 → 持倉與估值 → 風險／績效 → 交易提案 → 獨立覆核 → 模擬成交 → 對帳。數值與限制由確定性程式計算，AI 只讀取已授權的證據並提供草稿說明。

Java／Spring 服務預計擁有提案版本、狀態轉換與 audit/outbox，不能直接改寫 Python 帳簿資料。Kafka 等跨服務需求成立後再導入；重試與至少一次投遞需要去重，不宣稱端到端 exactly-once。先做模組化單體，仍可展現企業工程判斷。

企業級規格必須能驗收：持倉與現金可核對、過期資料會阻擋、建立者不能自批、輸入變更使舊批准失效、重試不重複交易、資料可復原、AI 引用與權限可測。這些目前多為目標規格；已實作範圍以 [Roadmap](../ROADMAP.md) 與測試證據為準。

本機 Compose 與資料卷名稱保留，不因 repository 更名刪資料。新的 GHCR image namespace 需要重新建置與發布；本次沒有部署雲端，也沒有證明 HA、效能或復原目標。
